Method

Three deterministic steps — no AI guessing

Governments spending public money must answer one question at audit time: who decided this, and on what basis? OpenShelter can answer it line by line. Here is exactly how a brief is produced.

1

Hazard fingerprint

Your coordinates are looked up in gridded public datasets — USGS earthquakes and NOAA cyclone tracks today; national flood & heat layers next. Every value carries its source label, and the engine refuses to hide which is which.

2

Code profile

Each jurisdiction's rules (Eurocode 8, IS 139, ASCE 7, NSCP, Sphere) live in machine-readable JSON anyone can inspect, diff and correct via pull request — owned by the countries themselves, not by a vendor.

3

Rule engine

Hazard × code produces ranked measures and compliance checks. Same inputs → byte-identical brief, forever. That determinism is what makes the output usable in audits, procurement and court-grade documentation.

Walkthrough

What happens when you click "Generate"

  1. Inputs are normalised. Latitude, longitude, population served and distance to water become a Site record. Nothing leaves your browser; the same code runs offline in the Python CLI.
  2. The hazard grid is sampled. Real grids (earthquake, cyclone) are read from bundled JSON derived from public-domain catalogues. Placeholder layers are computed deterministically and flagged as demo in the output itself.
  3. The code profile is loaded. A JSON file like in-is139-is4352.json contains thresholds, clauses and citations — e.g. "set floor level ≥ 0.6 m above highest recorded flood; cite IS 139 §4.2".
  4. Rules fire in priority order. Each triggered rule emits a recommendation carrying: priority (P1 critical → P3 advisable), the hazard value that fired it, and the exact clause reference.
  5. Compliance checks run. Machine-verifiable pass/review states (occupancy area per person, WASH ratios, freeboard) are computed against your population figure.
  6. The brief renders. JSON, Markdown or printable HTML — all three diff-stable, version-stamped, and citable by URL.
Principles

Why "explainable" beats "smart"

A model that can't cite a clause can't survive an audit

Neural networks are brilliant at pattern-matching and hopeless at accountability. When a ministry defends shelter spending before a public accounts committee, "the algorithm said so" is not an answer. Every OpenShelter recommendation prints the hazard value and the exact code clause that produced it. No hidden model, no proprietary data, no subscription.

What it deliberately does NOT do

It does not replace a licensed structural engineer, stamp drawings, or claim site-specific geotechnical truth. It closes the gap between "no plan at all" and "an unaffordable consultancy" by producing the pre-design brief that makes the engineer's job faster, cheaper and locally appropriate.

Determinism is a feature, not a limitation

There is no randomness, no learning-at-runtime, no telemetry-dependent behaviour. Given identical inputs and an identical code-profile version, OpenShelter will produce the same brief in 2030 that it produces today — which is precisely what archivists, auditors and litigators need.

Federated ownership of legal text

Building-code wording is copyrighted in many jurisdictions, and getting it wrong has legal consequences. So each national profile is a declarative JSON file maintained through pull requests reviewed by (ideally) that country's standards community. Adding Bangladesh's BNBC does not require waiting on the core team — it requires one file and one PR.
