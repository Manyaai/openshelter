# Funding map & sustainability strategy

## Why governments fund this
- **Sendai Framework Monitor / Target E**: countries must report risk-informed
  reconstruction capacity; this is directly usable evidence tooling.
- **Public-procurement law fit**: AGPL open source satisfies "public code"
  mandates (EU Public Service Rule, US Federal Source Code Policy, India's
  open-source procurement preference).
- **Auditability**: deterministic JSON briefs diff-able in git satisfy
  supreme-audit-institution traceability requirements for disaster spending.

## Concrete funding windows (examples, verify current calls)
| Programme | Fit |
|---|---|
| Horizon Europe HORIZON-CLIMA-Cities / civil protection calls | disaster-resilient built environment, open science requirement |
| Green Climate Fund – Readiness & Preparatory Support | tooling for NDC adaptation in shelter/reconstruction |
| USAID / BHA & GFDRR (World Bank) grants | risk-informed reconstruction, open data |
| EU DG ECHO innovation actions | humanitarian shelter design workflows |
| National DMOs (e.g. BNPB Indonesia, NDRRMC Philippines, NDMA Pakistan) | localize code profiles = small funded contracts per country |
| Sovereign Tech Fund / NLnet / GitHub Accelerator-type OSS funds | core engineering |

## Revenue model (non-extractive)
1. Grants for core + per-country profile localization (paid to national partners).
2. Dual licensing: commercial embedding licences for engineering firms/OEMs.
3. Hosted-but-open deployment support for ministries (SLA, training, CI for their profiles).
4. Certification/training for local engineers using the brief workflow.

## Exit-ramp from grant dependency
Federated profile ownership means each ministry maintains its own code JSON in
fork-or-upstream — maintenance cost scales with users, not with the core team.
